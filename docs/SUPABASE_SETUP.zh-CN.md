# 产品数据库与管理员配置（第一阶段）

## 当前范围

本文件提供可审查的数据库配置，不表示已执行。现有 `/admin/` 仍是内存原型，尚未接入数据库。没有询价表、客户附件桶或自动发布逻辑。

请只在刚创建的 `sift-bearing-store` 项目执行。不要在已有业务数据库盲目重跑；迁移为一次性脚本，重复运行会报对象已存在并回滚。先保留数据库密码，不要粘贴进 SQL 或 GitHub。

## 1. 先锁定注册入口

在 Supabase 的 Authentication 设置中找到允许新用户注册（Allow new users to sign up / Enable new user signups，具体界面可能变化），关闭公众自行注册。保留 Email 登录，管理员通过控制台手动创建。若有匿名登录选项，保持关闭。

以后接入时再设置实际 Site URL 和允许的重定向 URL；不要使用宽泛通配符。建议为你的 Supabase 平台账号启用多因素认证。平台登录与网站管理员登录是不同身份。

## 2. 创建数据库结构

1. 打开项目侧栏 **SQL Editor → New query**。
2. 将 `supabase/migrations/202610270001_product_management.sql` **完整内容**复制进去。
3. 确认项目名称正确，使用控制台默认的数据库管理角色运行一次。
4. 成功后，应出现 `sift_products` 和 `sift_product_images` 两张公开 schema 表，以及私有 schema 中的管理员表。
5. Storage 应出现 **私有**桶 `sift-product-images`，每张图限制 10 MB，只允许 JPEG、PNG、WebP。

若报错，保留报错文字并停止，不要删除旧表、关闭 RLS 或手动放开所有权限。脚本使用事务；这一步不插入产品，不影响现有网站和 DNS。自动 RLS 的平台设置不是替代品，脚本仍显式启用 RLS。

## 3. 创建唯一管理员

在 **Authentication → Users** 中用控制台提供的新增用户方式创建你自己的账号：

- 使用你本人可收信的邮箱。
- 密码自行生成并安全保存，不在聊天、文档或 GitHub 中分享。
- 使用“创建用户”或“邀请用户”要按控制台实际流程完成邮箱验证；邀请邮件交付可能需要后续邮件配置。
- 复制该用户的 **User UID**。它不是数据库密码。

然后在 SQL Editor 中运行以下片段，**仅把占位符换成刚创建的用户 UUID**：

```sql
insert into sift_private.administrators(user_id)
values ('替换为你的管理员用户UUID'::uuid)
on conflict (user_id) do nothing;
```

必须是你自己的 Auth 用户，不要使用项目 ID、邮箱或随机 UUID。只有 SQL 管理员可操作这张私有白名单表；普通注册用户即使能登录也没有产品管理权限。撤销管理员可删除对应白名单行；不要删除整个项目。

## 4. 只读检查

在 SQL Editor 执行 `supabase/verify_product_security.sql`：

- 两张产品表 `rls_enabled` 均为 `true`。
- 桶 `public` 为 `false`，限制 10485760 字节。
- 管理员数量：登记前为 0，登记后为 1。
- 能列出产品、图片及存储的权限策略。

这些是配置检查，**不是完整的安全验收**。接入后还必须使用真实匿名客户端、非管理员测试账号和管理员分别测试权限，不能只在绕过 RLS 的 SQL 管理员身份下测试。

## 5. 权限设计

| 访问者 | 已发布产品/图片 | 草稿/下架 | 修改产品、图片 |
| --- | --- | --- | --- |
| 未登录访客 | 可读 | 不可读 | 不允许 |
| 已登录但未登记管理员 | 可读 | 不可读 | 不允许 |
| 白名单管理员 | 可读 | 可读 | 允许 |

原图桶不是完全公开：使用应用生成的短时签名链接读取。匿名访客只有对应已发布产品的图片记录才可读取，不能读取草稿原图。已发出的签名链接在到期前可能仍有效，下架不等于立即撤销所有已发链接。已下载或缓存的图无法追回。

存储采用 `产品UUID/图片UUID.webp` 等名称；产品图片元数据按位置排序，0 为封面，重排通过事务函数完成。禁止原地覆盖对象，替换时上传新文件。删除产品记录不会自动删除 Storage 文件；接入应用时应实现明确清理流程，失败重试，避免孤立对象。

未来公开优化后的产品图片可能采用独立公开桶/CDN；不能为了展示方便将当前原图桶改成公开，更不能混入客户附件。

## 6. 后续应用接入与验收

数据库配置完成后再实现：管理员会话、上传、草稿保存、发布和双语前台读库。当前原型中的“发布至少一张图”等只是演示约束，数据库基础迁移并未实现完整发布工作流。

后续需要项目 URL 和 publishable key（旧项目可能称 anon key）。它们不是管理员密钥，但仍应在配置步骤按需填写；RLS 才是数据安全边界。**不需要你提供数据库密码、Secret key 或 service_role key 给聊天。** 服务端密钥如将来确需使用，只在托管平台的安全环境变量中配置，绝不能进入 Vite 的 `VITE_` 浏览器变量。

集成验收清单：

- 匿名和非管理员不能插入、修改、删除产品或上传文件。
- 匿名不能查询草稿/下架产品、图片，不能签发其存储链接。
- 管理员保存后刷新仍存在，双语内容及图片排序正确。
- 相同品牌和完整型号（不区分大小写）不能重复。
- 发布/下架会正确刷新前台，不沿用演示产品。
- 非法类型及超限图片被拒绝，上传失败不发布半成品。
- 导出产品与图片备份后，实际演练恢复；本迁移不提供自动备份。

## 第二阶段：真实登录和产品保存（新增）

代码现在提供两个明确入口：

- `/admin/`：真实后台。未配置时只显示配置提示；配置后先登录并检查管理员白名单。
- `/admin-demo/`：原来的内存演示，永不访问数据库。

### A. 运行第二份 SQL（不要重复第一份）

确认第一份已成功、管理员已登记后，新建 SQL Editor 查询，完整运行：
`supabase/migrations/202610270002_atomic_product_save.sql`。

这份脚本只增加 `sift_save_product` 事务函数，不重建已有表和存储桶。它同时保存产品文字、图片关联、顺序和发布状态，校验真实存储对象与产品目录匹配，发布至少需要一张图。没有执行它，后台会提示找不到 RPC 函数。

### B. 填写环境变量

本地开发：复制项目根目录 `.env.example` 为 `.env.local`，填入：

```text
VITE_SUPABASE_URL=https://你的项目标识.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=你的Publishable或旧版anon密钥
```

URL 可在项目连接/API 设置查看。公开 key 可在 API Keys 查找；**Secret key、service_role 和数据库密码均不可使用**。`VITE_` 值会进入浏览器，不适合存储秘密；代码拦截常见 server key 只是辅助，不能代替正确配置。

修改环境变量后重启开发服务；Vercel 需要在项目环境变量中配置并重新构建。Vite 会在构建时嵌入值，不能只改静态成品环境。未配置时不会连接任何项目，不会混入演示数据。

不要将 `.env.local` 放入 Git。模板不含任何真实凭据，允许提交。

### C. 真实操作边界

- Supabase 会话保存在当前浏览器。仅在受信任设备登录，离开时退出。
- 每次加载/保存会验证身份，数据库与存储权限仍由 RLS 强制执行。
- 新建时先存私有草稿，再上传图片，最后事务保存元数据和目标状态。失败可能保留草稿或孤立文件；先刷新核对，不要反复创建同型号。
- 已存在产品的元数据保存为一个事务。网络中断时可能已经成功，先刷新核对。多个管理员窗口同时编辑目前是最后保存覆盖，请避免并发编辑。
- 图片移除只移除关联，不立即物理删除对象；避免不确定提交结果或并发场景误删。后续增加孤立文件审查清理。存储可能继续计费，需要定期检查。
- 图片签名链接有效期 15 分钟，过期后点击“刷新资料”重新获取。
- 当前最多加载最近 500 款，批量导入、完整分页、图片压缩、业务导出尚未实现。
- **首页仍为固定演示产品，尚未读库。数据库“发布”状态不会自动替换现有首页。** 前台读库及双语详情是下一个开发阶段。
- 未连接真实询价；客户清单不要上传到产品图片桶。

### D. 验收与测试说明

开发环境可运行 `npm test`。测试覆盖登录/非管理员阻断、无配置提示、存储文件类型/大小限制、发布图片要求、草稿创建及保存事务的调用顺序，使用模拟客户端，不会连接你的项目。

这些不是线上 RLS 验证。请先使用无敏感资料的测试产品，执行前文匿名、普通用户、管理员三种身份的验收；再检查私有桶与限制。真实项目未完成这些验证前，不视为可正式上线。

## 第三阶段：访客隔离检查与首页产品读取

无需额外 SQL 或重新上传产品。刷新真实后台，点击 **访客权限检查**：

- 使用独立、无管理员会话且不持久化登录的客户端。
- 检查访客管理员身份应为 false。
- 对当前已加载的最多 10 款草稿/下架产品，检查产品与图片记录返回空数组。
- 对其已知图片路径，检查匿名签名链接申请被拒绝（每款最多 30 张）。
- 网络、API key 或服务错误显示“未确认”，不算通过。检查不写入、不删除、不切换产品状态。
- 此检查不覆盖匿名写入、普通登录用户、公共桶直链、历史签名链接及所有项目安全配置；完整上线验收仍需补充这些场景。

前台产品区现在在已配置环境下读取真实数据库，最多展示最近更新的 9 款已发布产品；尚无发布产品会显示询价引导。读取失败显示错误及重试，不回退为演示数据。未配置环境仍保留原来的静态视觉样例。首屏及其他静态实拍素材仍是过往产品示例，与实时数据库库存无关。

首页使用同样独立的访客连接，避免管理员浏览前台时草稿意外可见。已发布产品可打开多图相册，英/西语采用对应说明，空说明不伪造参数；点击询价将品牌和型号带入清单。

前台图片签名有效期 5 分钟，可见页面每 4 分钟重新取数；发布/下架后手动刷新页面立即取最新资料。已打开的相册和已发签名 URL 不会瞬间撤销；需按有效期和缓存边界理解。私有原图签名不是防下载系统。后续正式 SEO 产品详情仍需服务端渲染/预渲染、稳定 URL、规范链接和 sitemap，当前相册不是可独立收录的产品详情页。

建议验收顺序：保持 BA165-203 为草稿 → 运行访客检查并核对结果 → 前台确认无该产品卡片 → 确认所有相关检查通过后手动发布 → 刷新英/西语首页核对封面、排序及清单填入 → 下架后刷新确认卡片消失。
